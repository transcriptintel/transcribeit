# TI-003 — Output and command orchestration exceed maintainable boundaries

## Required outcome and acceptance

Split the 841-line `pipeline_output.rs` by manifest construction, capabilities,
quality, and cache telemetry while retaining a thin output coordinator. Extract
command dispatch and provider construction from the 730-line `main.rs`, preserve
the exact CLI and provider contracts, lower module-size exceptions, and replace
gitignored findings as the engineering source of truth with a tracked,
validated `docs/issues/TI-NNN.md` registry.

## Outcome and validation

`pipeline_output` is now a directory module with 196-line-or-smaller production
components and tests beside their owning boundaries. `main.rs` is a 43-line
entry point; setup/download/list routing lives in `command_dispatch.rs`, batch
run policy lives in `run_command.rs`, and local/OpenAI/Azure/Qwen/Gemini/Riva/
Deepgram construction lives in focused provider-factory modules.

The two obsolete module-size exceptions were removed, reducing the reviewed
budget from 14 to 12. Focused output, provider-factory, Gemini compatibility, and
CLI secret-sentinel tests passed. `./scripts/check.sh` passed 92 unit tests plus
the CLI security test, policy/hook tests, three Bun registry tests, module and
skill validation, formatting, and strict default Clippy. The all-feature suite
passed 97 unit tests plus the CLI security test and strict all-feature Clippy.
The all-feature build, actionlint, ShellCheck, shell syntax, Taskfile parsing,
registry generation/checking, 18-file Markdown link validation, and
`git diff --check` also passed. Doc tests are not applicable because this package
has no library target. No live provider or deployed runtime was used for this
pure structural and governance change.

# TI-005 — Decide whether to package llama.cpp Qwen3-ASR support

## Required outcome and acceptance

Turn the existing exploratory OpenAI-compatible `llama-server` path into a clear
product decision. If packaging proceeds, define server discovery or lifecycle,
startup/readiness and shutdown behavior, default model selection, artifact
ownership, timeout and cleanup behavior, provider metadata, and a timestamp or
alignment contract. If it remains external-only, document that boundary and the
supported generic base-URL configuration without implying managed lifecycle.

Acceptance requires reproducible 0.6B and 1.7B evidence on the representative
corpus, explicit memory and warm/cold latency observations, and a decision that
does not compromise the standalone-binary expectation accidentally.

## Outcome and validation

Resolved as **external-only**. TranscribeIt retains the generic OpenAI-compatible
`--provider openai --base-url` path for a user-managed Qwen3-ASR `llama-server`,
but will not add a dedicated llama.cpp provider or package its runtime and GGUF
artifacts. This preserves an explicit opt-in experiment without expanding the
standalone binary into a sidecar process and multi-artifact model manager.

### Representative-corpus evidence

Short fixtures used three requests against one cached 16,384-token server per
model; AMI used one cached 65,536-token server per model.

| Model | Short macro WER | AMI wall / RTF | AMI WER | Short / long peak RSS |
|---|---:|---:|---:|---:|
| Qwen3-ASR 0.6B Q8 | 46.50% | 187.10s / 0.0772 | 33.86% | 3.47 / 8.63 GiB |
| Qwen3-ASR 1.7B Q8 | 46.50% | 534.12s / 0.2204 | 102.26% | 4.79 / 10.10 GiB |

Both models produced identical transcript hashes on all three short fixtures:
41.18% WER on clean and noisy FLEURS and 57.14% on the Mandarin-L1 English
fixture, with 100% tracked-term recall. On AMI, 0.6B retained 100% of tracked
terms and 1.7B retained none. The larger model therefore provided no observed
short-form quality gain and regressed sharply on this long-form fixture.

Empty-cache download plus load took 190.59s for 0.6B and 225.87s for 1.7B on the
evaluation network. Cached 16,384-token startup was 1.64s and 2.24s; cached
65,536-token startup was 2.48s and 2.87s. The meeting audio prompt required
31,527 tokens, so both models explicitly rejected the first 16,384-context
attempt before inference. The successful 65,536-context repeats exposed the
material long-form memory increase recorded above.

### Capability and lifecycle boundary

Both model sizes returned one zero-duration text segment. Neither exposed native
segment or word timestamps, speakers, detected language, emotion, or provider
metadata through the tested OpenAI-compatible endpoint. TranscribeIt therefore
does not claim subtitle or diarization support for this path.

The external operator owns server/model discovery, downloads and integrity,
startup and readiness, context sizing, request capacity, logs, updates, shutdown,
retention, and cleanup. TranscribeIt owns only audio preparation, the compatible
HTTP request, error reporting, and conservative response normalization.

### Cleanup and acceptance result

The evaluation-owned directory was absent before the run. After sanitizing the
metrics and hashes, its llama.cpp runtime, both isolated Qwen caches, and all raw
transcript artifacts were deleted. The exact path was verified absent, reclaiming
3,579,596,800 bytes.

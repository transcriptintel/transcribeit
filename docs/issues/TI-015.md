# TI-015 — Avoid redundant Apple Speech media conversion

## Required outcome and acceptance

Preserve Apple Speech's native whole-file processing path by passing the original
media file to `AVAudioFile` when normalization and segmentation were not
requested. Large supported files must not be decoded and re-encoded merely to
enter the Apple provider.

If `AVAudioFile` rejects the original input, retry once with TranscribeIt's
canonical mono 16 kHz temporary WAV. Keep explicit `--normalize` and `--segment`
behavior unchanged, do not retry unrelated Apple availability, locale, asset, or
transcription failures, and preserve temporary-file cleanup. Acceptance requires
focused preparation-policy and fallback classification regressions, updated
provider and architecture documentation, a direct M4A runtime smoke on eligible
macOS hardware, and the default Rust repository gate.

## Outcome and validation

Resolved by adding a provider media-preparation capability to `Transcriber`.
Apple Speech opts into original whole-file media when normalization,
segmentation, automatic splitting, and provider upload encoding are inactive.
Its Swift FFI now returns a bounded numeric failure code alongside the sanitized
message. Only the AVAudioFile read code causes a single temporary mono 16 kHz WAV
conversion and retry; all availability, Apple Intelligence, Speech, locale,
asset, transcription, malformed-response, and unknown failures remain terminal.
The temporary WAV remains scoped to the retry and is deleted on drop.

Validation completed on 2026-08-17:

- focused regressions proved that M4A reaches an original-media engine under its
  original path, explicit normalization still prepares WAV, and only the typed
  audio-read failure is eligible for fallback;
- a generated 3.551-second M4A completed through real Apple Speech without a
  conversion message, while generated WebM produced the expected AVAudioFile
  rejection, one WAV fallback, and a successful provider-native transcript;
- the real 34,237,539-byte, 3,234.752-second private Japanese interview fixture
  completed directly with no conversion. Output
  review rejected the initial system-default `en_US` smoke as quality evidence:
  it produced only 28 sparse segments and 597 characters. An explicit `ja-JP`
  run resolved to `ja_JP`, completed in 38.11 seconds, and produced 214 non-empty,
  unique provider-native segments with 16,348 characters through 3,232.8 seconds;
  every segment had positive, non-reversed timing;
- transcript content was not printed or retained. The synthetic 248 KiB,
  initial large-file 20 KiB, and locale-comparison 312 KiB evaluation-owned
  output directories were each deleted with narrow exact paths and verified
  absent; the source interview was untouched;
- `./scripts/check.sh` passed with 104 unit tests, one CLI security integration
  test, exact strict Clippy, formatting, repository/hook tests, module-size,
  skills, issue-registry, corpus, and benchmark-matrix validation.

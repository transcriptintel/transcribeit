# TI-007 — Rebaseline the hosted and local provider comparison

## Required outcome and acceptance

Re-run the current OpenAI, Azure where configured, DashScope Qwen, Gemini,
Deepgram, NVIDIA Riva, whisper.cpp, Sherpa-ONNX, and supported local-compatible
providers under the tracked benchmark protocol and the representative corpus.
Record exact model revisions or resolved identifiers, commands, preprocessing,
warm/cold state, retries, machine and tool versions, fixture hashes, artifact
hashes, capability metadata, and sanitized raw result records.

Acceptance requires repeated latency runs, honest failure and unsupported-format
records, reviewed quality evidence, and clean-baseline classification. The dated
2026-06 observations remain historical context and must not be silently relabeled
as regression baselines.

## Five-minute compatibility reference (2026-08-06)

The configured provider and local-engine matrix was rerun three times on the
available five-minute fixture. The sanitized reference record is
[`2026-08-06-ti-007-provider-rebaseline.sanitized.json`](../../benchmarks/results/2026-08-06-ti-007-provider-rebaseline.sanitized.json).
It covers Azure, Deepgram, Gemini, NVIDIA Riva, OpenAI `gpt-transcribe`, OpenAI
`gpt-4o-transcribe-diarize` with `diarized_json`, DashScope Qwen FileTrans,
whisper.cpp base, Sherpa-ONNX Whisper base, and Qwen3-ASR 1.7B through llama.cpp.

The record includes run-level latency and artifact hashes, model/deployment
identifiers, preprocessing and warm-state boundaries, reviewed seven-term
presence evidence, provider capability metadata, remote staging cleanup, local
download cleanup, and deterministic failure records. `gpt-transcribe` continued
to reject `response_format=diarized_json`; current speaker-labeled output succeeds
with `gpt-4o-transcribe-diarize` and `chunking_strategy=auto`.

All downloadable artifacts used new evaluation-owned directories. Five download
cycles removed 4,278,595,584 bytes in total, and every exact evaluation path was
verified absent afterward. The cycles include successful measurements as well as
the Sherpa missing-VAD and unsupported-VTT attempts.

## Representative-corpus reference (2026-08-06)

The full ten-provider matrix was then run against the tracked TI-006 corpus. The
three short fixtures have three repetitions per provider and the 40-minute AMI
meeting has one repetition per provider. Of 100 attempts, 99 produced
transcripts. The reviewed, transcript-free record is
[`2026-08-06-ti-007-representative-corpus.sanitized.json`](../../benchmarks/results/2026-08-06-ti-007-representative-corpus.sanitized.json).

On the long AMI fixture, Deepgram `nova-3` had the lowest observed WER (18.45%)
and the lowest scoreable diarization error rate (25.60%). Qwen FileTrans and
OpenAI `gpt-transcribe` followed at 21.19% and 22.57% WER. These are single-run,
dirty-worktree observations rather than a provider leaderboard. The AMI
reference contains overlapping speech, so WER must be interpreted with the
recorded timing, DER, and attributed-WER measurements.

OpenAI `gpt-4o-transcribe-diarize` completed all nine short runs, but rejected
the 2,423.68-second AMI fixture because it exceeded the returned 1,400-second
input limit. A separate direct probe confirmed that `gpt-transcribe` still
rejects `response_format=diarized_json`; no transcript was produced by either
failed request. Azure completed all attempts with three recorded retry events.

Every downloadable model used a new evaluation-owned directory. The run removed
3,228,049,408 bytes after evidence capture and verified the evaluation root was
absent. All ten Gemini Files API and Qwen staging cleanup attempts also succeeded.

The run found and fixed one corpus metadata defect: the reviewed FLEURS reference
says `predicted`, while its domain-term list said `prediction`. Corpus validation
now rejects inline domain terms that cannot occur in the normalized reviewed
reference.

## Remaining acceptance work

This issue remains in progress. Both reference records were produced from a
dirty worktree, so neither is eligible to become the clean regression baseline.
Repeat the representative-corpus matrix from a clean commit, preserve the same
scoring and failure classifications, and review the sanitized record before
marking TI-007 resolved.

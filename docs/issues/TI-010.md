# TI-010 — Retire the unused Sherpa-ONNX integration

## Required outcome and acceptance

Remove the unused Sherpa-ONNX runtime rather than carrying an unowned native
dependency stack. This includes the provider, feature and dependencies, ONNX
model/setup paths, Silero VAD, local speaker diarization, native bootstrap and
linking, CI coverage, and active CLI/documentation surfaces.

Acceptance requires that former CLI surfaces are rejected, unsupported local
diarization requests fail before transcription, current docs and skills no
longer instruct users to install Sherpa, and the default repository checks pass.
Dated issues, benchmark prose, and sanitized result records must remain as
historical evidence, with a retirement note that distinguishes them from current
support.

## Outcome and validation

Resolved by deleting the Sherpa provider and FFI engine, all ONNX/VAD/local
diarization modules, native bootstrap and linker configuration, setup/model
paths, optional dependencies, and the redundant all-feature CI job. Cargo now
has no optional features and its resolved normal/build dependency tree contains
no Sherpa, ONNX Runtime, `tar`, or `bzip2` packages.

The maintained CLI supports seven providers and GGML-only managed local models.
Regression tests confirm former Sherpa provider, ONNX format, VAD model, and
Sherpa setup component arguments are rejected. A separate request-boundary test
confirms local post-processing diarization is rejected while supported provider
diarization remains accepted. Current docs, workflows, repository instructions,
and skills were updated; dated TI-004/TI-007 and benchmark evidence remains
linked from the [retirement note](../retired/sherpa-onnx.md).

Validation completed on 2026-08-06:

- `./scripts/check.sh` passed with 91 unit tests, one CLI security integration
  test, strict Clippy, formatting, policy/hook tests, module-size checks, skills,
  issue registry, and corpus validation;
- the equivalent all-feature test and strict Clippy commands passed after the
  feature removal;
- `cargo audit --deny warnings`, `actionlint`, `bash -n`, and `shellcheck` passed;
- Cargo metadata/dependency and generated CLI-help negative checks found no
  active Sherpa/ONNX feature, package, provider, option, or setup component;
- local Markdown links passed across 20 README, docs, and benchmark files.

No live provider call was required because the supported remote provider request
and response contracts were unchanged.

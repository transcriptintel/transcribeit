# TI-012 — Preserve zero-duration text in subtitle output

## Required outcome and acceptance

Allow VTT and SRT output to complete when an otherwise timed provider transcript
contains an isolated zero-duration text segment, including the equal native
timestamps observed from local whisper.cpp. Preserve the segment text and any
speaker label without inventing a new timestamp or hiding the provider defect in
the manifest.

Acceptance requires a shared subtitle normalization rule that folds each
zero-duration text segment into the nearest positive-duration cue while retaining
the original text order and per-line speaker attribution. Negative, reversed,
non-monotonic, and completely untimed transcripts must remain rejected. The raw
manifest must retain the provider timestamps, report the zero-duration quality
warning, and keep `quality.timing_reliable` false. VTT, SRT, pipeline, and
documentation regressions plus the default repository gate must pass.

## Outcome and validation

Resolved with a shared subtitle cue preparation layer used by both VTT and SRT.
It keeps provider segments and timestamps unchanged, validates structural timing,
and assigns each isolated zero-duration text segment to the closest
positive-duration cue. Lines are collected in original transcript order, and
each line retains its own speaker label. Equal-distance boundary segments prefer
the preceding cue. Empty zero-duration segments are omitted from subtitle text.

The manifest continues to serialize the provider-native segment list. Its
quality calculation therefore records the zero-duration warning and keeps
`timing_reliable` false even though the subtitle output is usable. Negative,
reversed, non-monotonic, and wholly untimed segment sets still fail subtitle
serialization.

Validation completed on 2026-08-17:

- focused output tests passed for leading and trailing equal-timestamp segments,
  nearest-cue selection, source order, VTT/SRT rendering, and speaker retention;
- an end-to-end local `large-v3`-shaped pipeline regression passed, writing VTT
  while retaining `1000ms..1000ms` in the manifest and its quality warning;
- `./scripts/check.sh` passed with 95 unit tests, one CLI security integration
  test, strict Clippy, formatting, policy and hook tests, module-size checks,
  skill validation, issue-registry validation, corpus validation, and benchmark
  matrix validation;
- no live provider call was required because the defect is deterministic output
  normalization over an already observed local whisper.cpp response shape.

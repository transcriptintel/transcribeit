# TI-013 — Add an Apple Speech on-device provider

## Required outcome and acceptance

Add `apple-speech` as a macOS-only provider backed by Apple's on-device
`SpeechAnalyzer` and `SpeechTranscriber` APIs through a narrowly scoped Swift
bridge. Do not call this provider `afm`: Foundation Models supplies the requested
Apple Intelligence availability gate, but speech-to-text is performed by the
Speech framework rather than a foundation model.

Acceptance requires macOS 26 or later, available Apple Intelligence, supported
Apple Speech hardware and locale, and a system-managed locale asset. Non-macOS
targets must still compile and must reject `--provider apple-speech` before media
preparation. The provider must accept `--language`, return native segment timing,
produce text/VTT/SRT/manifest output, avoid diarization claims, and record only
sanitized locale, on-device, availability, and asset-installation metadata.

The bridge and response parser must bound data crossing FFI, reject malformed
timing without exposing transcript text or local paths, and run blocking native
work outside Tokio's async workers. Release builds must retain the existing
Linux, Windows, Intel macOS, and Apple Silicon macOS matrix; the provider is
usable only where its runtime gate passes. Documentation, platform/build tests,
a local runtime smoke test when the host is eligible, and the default repository
gate must pass.

## Outcome and validation

Resolved with the public provider name `apple-speech`. The implementation adapts
IntelliNotes' proven Rust/Swift bridge shape to TranscribeIt's provider contract,
while using the current Apple APIs: `SpeechAnalyzer` and `SpeechTranscriber`
perform ASR, and `SystemLanguageModel` supplies only the requested Apple
Intelligence availability gate.

The macOS-only Swift bridge is compiled as a static library from `build.rs` and
weak-links Speech and FoundationModels. All macOS 26 symbols are availability
guarded, so the TranscribeIt binary retains its macOS 11 deployment target and
other providers still launch on older macOS versions. Linux and Windows retain
the CLI enum but reject `apple-speech` before input discovery or FFmpeg work.
The Intel Swift target type-checks even though Intel hardware is expected to fail
the Apple Intelligence eligibility gate.

The provider resolves `--language` through Apple's supported-locale API, installs
the required system-managed speech asset when requested, and returns native
segment timing plus resolved locale metadata. It does not claim word timestamps,
speakers, diarization, emotion, or token caching. Blocking Swift/AVFoundation
work runs under `spawn_blocking`. FFI payload length is checked before copying,
JSON is capped at 64 MiB and 200,000 segments, and malformed timing errors omit
transcript content and input paths.

Validation completed on 2026-08-17:

- a real on-device VTT smoke passed on Apple M4 Pro, macOS 26.5.2 build 25F84,
  Swift 6.3.3, and the macOS 26.5 SDK with Apple Intelligence available;
- the smoke produced one provider-native timed cue, `timing_reliable: true`,
  resolved locale `en_US`, sanitized `apple-speech.metadata.v1`, and a macOS
  locale-asset installation request;
- the final bounded-ABI smoke's 148 KiB evaluation-owned audio/output directory
  was deleted and verified absent; the shared speech asset remains under macOS
  ownership as required by Apple's lifecycle contract;
- both arm64 and x86_64 Swift targets compiled/type-checked, the locked optimized
  release build passed, and `otool` confirmed weak Speech/FoundationModels loads
  with an unchanged macOS 11 minimum;
- `./scripts/check.sh` passed with 101 unit tests, one CLI security integration
  test, strict Clippy, formatting, policy/hook tests, module-size checks, skills,
  issue registry, corpus, and benchmark-matrix validation;
- `cargo audit --deny warnings` still reports only the pre-existing
  RUSTSEC-2026-0253 advisory tracked by TI-011; this provider added no Cargo
  dependency;
- the unchanged Linux, Windows, Intel macOS, and Apple Silicon release jobs
  remain the authoritative cross-platform build evidence after the changes are
  committed and pushed.

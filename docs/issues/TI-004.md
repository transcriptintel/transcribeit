# TI-004 — Evaluate a native Rust ONNX path for Qwen3-ASR

## Required outcome and acceptance

Determine whether a validated Qwen3-ASR ONNX export can preserve TranscribeIt's
compiled-binary product boundary without a Python runtime or separately managed
server. The evaluation must cover tokenizer and feature-extractor parity,
transcript quality, timestamps or alignment, supported languages, model artifact
pinning and verification, memory/latency behavior, packaging stability, and
failure reporting on at least the representative benchmark corpus.

Do not add the provider merely because inference can be invoked. Acceptance
requires a maintainable Rust runtime path, reproducible artifact identity,
documented capability limits, and evidence that normalization does not overclaim
timestamps, speakers, or metadata the model does not actually supply.

## Outcome and validation

Accepted through the existing optional `sherpa-onnx` provider. The implementation
runs the maintained Sherpa Qwen3-ASR ONNX export in-process and keeps the compiled
binary boundary: it adds no Python runtime, sidecar server, or direct model-stack
dependency. `sherpa-onnx` and its native package were updated from 1.13.2 to
1.13.4; the remaining direct Rust dependency audit also updated `sha2` to 0.11.0
and reports all direct dependencies current.

### Selected artifacts

- Model: `sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25`
- Model archive: 878,702,423 bytes,
  SHA-256 `393f8a14e2f5fb96746aaab342997a40641001fbd5bf9592a080a8329178ee96`
- Installed model tree:
  `d82e0c1096f0018318ccca71b91f3dff616a67b81c09cdcb5f52392b2d7f4df7`
- Runtime: Sherpa 1.13.4 with ONNX Runtime 1.27.0
- Managed aliases: `qwen3-asr` and `qwen3-asr-0.6b`
- Install command: `transcribeit setup --component qwen3-asr`

The 0.6B int8 package was selected because it is the newest maintained official
Sherpa Qwen3-ASR export. Official Qwen 0.6B and 1.7B Transformers and vLLM model
revisions were reviewed, but there is no maintained official Sherpa 1.7B ONNX
package to pin. The separate Qwen forced aligner was not bundled: it adds another
model/runtime path, is documented for audio up to five minutes, and is absent
from the Sherpa Qwen package.

### Runtime and normalization contract

- Model detection requires `conv_frontend`, encoder, decoder, and `tokenizer/`;
  Qwen is checked before Whisper because both contain encoder/decoder graphs.
- Int8 encoder/decoder graphs are preferred.
- Sherpa auto-detects language, but its Qwen config has no language-hint field and
  does not expose the detected language. `--language` is therefore rejected.
- The current result exposes transcript text only. It does not expose native
  timestamps, words, speakers, or language metadata. Manifests retain zero-duration
  text segments with unreliable-timing warnings and never claim those capabilities.
- Segmentation remains automatic. Qwen3-ASR is capped at 20 seconds; other Sherpa
  architectures retain the 30-second cap.

### Representative-corpus evidence

The tracked sanitized record is
[`2026-08-06-ti-004-qwen3-asr-onnx.sanitized.json`](../../benchmarks/results/2026-08-06-ti-004-qwen3-asr-onnx.sanitized.json).
Short fixtures used three cold-process repetitions and AMI used one.

| FLEURS clean | 2.98s / 0.235 | 17.65% | 1.74 GB median RSS | 100% |
| FLEURS noisy 10 dB | 2.93s / 0.232 | 0.00% | 1.71 GB median RSS | 100% |
| SpeechOcean Mandarin-L1 | 1.88s / 0.627 | 0.00% | 1.55 GB median RSS | 100% |
| AMI ES2002c, 2,423.68s | 473.42s / 0.195 | 22.71% | 2.87 GB peak RSS | 100% |

The initial AMI run used the previous 30-second cap and failed on a 29.9-second
chunk after 80.06 seconds, at 3.12 GB peak RSS. A 20-second run completed, which
is the evidence for the model-specific cap. This dirty-worktree result is a
reference, not a clean-commit regression baseline.

### Packaging and cleanup

The official macOS arm64 1.13.4 package contained invalid embedded signatures on
its two ONNX Runtime dylibs, which caused the loader to kill the test binary.
Setup now verifies the archive first, repairs only those invalid signatures with
an ad-hoc signature, and reseals the installed tree. Linux and macOS x64/arm64
native archive identities are pinned in code.

The evaluation-owned model, VAD, and native-library directory did not exist
before the run. After evidence capture, the exact directory was removed and
verified absent, reclaiming 1,080,893,440 bytes of evaluation artifacts.

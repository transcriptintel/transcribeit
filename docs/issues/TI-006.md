# TI-006 — Build a representative multi-fixture transcription corpus

## Required outcome and acceptance

Replace single-interview quality observations with a legally usable, immutable,
and documented fixture set covering multiple accents, clean and noisy audio,
overlapping or multiple speakers, non-medical terminology, at least one
30-minute recording, and cases that expose timestamp and diarization behavior.
Each fixture needs a stable ID, duration, codec/container metadata, SHA-256, usage
rights, and reviewed reference text or an explicit no-ground-truth classification.

Acceptance requires a versioned corpus manifest and scoring rules that separate
word accuracy, domain-term handling, timing, speakers, metadata completeness,
latency, and provider failures. Raw sensitive interview material must not enter
the repository merely to make the benchmark convenient.

## Outcome and validation

Implemented `transcribeit-representative-v1` as a tracked YAML manifest with four
immutable fixtures: clean FLEURS US English, its deterministic 10 dB SNR noisy
derivative, clean Mandarin-L1 SpeechOcean762 English, and the 2,423.68-second
four-speaker AMI ES2002c meeting. The manifest records stable IDs, source and
output SHA-256 values, byte counts, duration, codec/container details, rights,
attribution, coverage dimensions, reviewed references, and timing/diarization
availability.

The Bun materializer downloads only HTTPS sources pinned by revision or content
hash, validates each source before use, confines output to the ignored
`samples/corpus/v1/` root, extracts declared archive members, verifies every
materialized artifact, and removes its temporary download cache by default. The
validated local corpus occupies 76 MB; no source archive or private interview is
tracked or retained by the materializer.

`benchmarks/corpus/v1/scoring.yaml` separately defines WER, domain-term recall,
timing error, speaker/diarization error, metadata completeness, latency, and
provider-failure accounting. Unsupported timing or speaker output remains a
capability result rather than being treated as zero error.

Validation on 2026-08-06:

- `bun run scripts/corpus.ts fetch` materialized and hash-verified all four
  fixtures and removed the temporary download cache;
- `bun run scripts/corpus.ts verify` verified all audio and 11 reference files;
- `bun test scripts/tests/corpus.test.ts` passed three manifest, containment,
  and deterministic-noise tests;
- `./scripts/check.sh` passed repository policy, hooks, six Bun tests, skill and
  issue validation, corpus validation, 92 Rust unit tests, one CLI security test,
  formatting, and Clippy with warnings denied.

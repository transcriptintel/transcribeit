# TI-016 — Require explicit Apple Speech locale selection

## Required outcome and acceptance

Prevent Apple Speech from silently using the current macOS locale when the
recording language may differ. A wrong locale can produce a sparse but
superficially valid transcript, so `apple-speech` must require an explicit
`--language` choice before input discovery or media preparation.

Accept BCP 47-style locale hints such as `ja-JP` and short language hints that
Apple can resolve, and accept `--language system` only as an explicit opt-in to
`Locale.current`. Reject an omitted value, an empty value, and `auto` with a
provider-specific actionable error. Preserve all other providers' existing
language defaults and keep the resolved Apple locale in sanitized provider
metadata. Acceptance requires focused positive and negative regressions,
updated CLI/provider/troubleshooting/examples, a live explicit-locale smoke on
eligible macOS hardware, and the default Rust repository gate.

## Outcome and validation

Resolved by validating Apple Speech's locale choice immediately after the
platform gate and before input discovery, FFmpeg checks, provider construction,
or media preparation. An explicit locale is preserved for Apple's supported-
locale resolution, `system` maps to an intentional `Locale.current` choice, and
omitted, empty, or `auto` values return provider-specific actionable errors.
Other providers retain their existing omitted-language and automatic-detection
behavior. Apple's resolved locale continues to be recorded in sanitized
provider metadata.

Validation completed on 2026-08-17:

- focused positive and negative unit tests covered explicit short and BCP 47
  locale hints, case-insensitive `system`, and rejection of missing, empty, and
  automatic choices;
- a macOS CLI regression proved that a missing Apple locale fails before a
  nonexistent input is discovered, while leaving the local provider contract
  unchanged;
- a generated AIFF completed through real Apple Speech with explicit `en-US`,
  produced VTT plus a manifest with one provider-native segment, and reported
  resolved locale `en_US` under `apple-speech.metadata.v1`;
- the live smoke's 204 KiB evaluation-owned audio/output directory was deleted
  with its exact path and verified absent;
- README, CLI reference, provider behavior, and troubleshooting guidance now
  document the required locale, rejected automatic mode, and explicit `system`
  opt-in;
- `./scripts/check.sh` passed with 108 unit tests, two CLI security integration
  tests, exact strict Clippy, formatting, repository/hook tests, module-size,
  skills, issue-registry, corpus, and benchmark-matrix validation.

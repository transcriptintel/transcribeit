# TI-008 — Add an automation-friendly benchmark harness

## Required outcome and acceptance

Create a harness only after the corpus and expected metrics are pinned. It must
capture the existing tracked metadata schema, execute exact provider/model
matrices without exposing credentials or transcript-bearing bodies, preserve
individual failures, sanitize publishable records, and distinguish local,
hosted, warm, cold, clean, and dirty runs. Concurrency and retries must be
explicit rather than hidden by the runner.

Acceptance requires deterministic fixture selection, resumable result storage,
schema validation, and tolerance rules that acknowledge host and provider
variance. CI must not fail on a tight latency threshold or incur unbounded live
provider cost; scheduled or manually approved remote execution remains a
separate policy decision.

## Outcome and validation

Resolved with the maintained Bun-native YAML harness at
`scripts/benchmark_harness.ts` and the reviewed example matrix at
`benchmarks/matrices/hosted-smoke.yaml`. The CLI validates and renders a
secret-free plan, runs an exact provider/model matrix, publishes an allowlisted
result, validates published records, and compares matching baselines. The
tracked matrix covers the six configured hosted providers with explicit
fixtures, model classifications, environment names, cold state, repetitions,
concurrency, retries, timeout, and report-only tolerances.

Run state is written atomically with immutable attempt keys and exact matrix and
binary SHA-256 identities. A resumed run preserves passed, failed, and
unconfigured attempts; resets interrupted attempts; and rejects changes to the
matrix, binary, or output-retention policy. Failures are categorized without
persisting stderr and are retried only through an explicit option. Fixture size
and SHA-256 are verified before execution, and CPU, memory, OS, architecture,
Rust, and FFmpeg identity are captured for the published record.

Publishing refuses incomplete runs and reconstructs attempts through strict
allowlists. Transcript text, stdout/stderr, request IDs, signed URLs, provider
error bodies, credential values, and local absolute paths are excluded. Attempt
transcripts and manifests are hashed and deleted by default. Nested environment,
tolerance, capability, quality, and sanitization fields are also allowlisted,
and comparisons require the same exact matrix-definition SHA-256. Hosted
execution requires `--allow-hosted`, cannot run under `local_ci`, and remains
report-only; only local CI matrices can enforce generous combined relative and
absolute latency tolerances.

Deterministic fake-provider coverage verifies successful and failed attempts,
rate-limit categorization, atomic resume without reruns, default output removal,
hosted opt-in, sanitized publishing, nested-field rejection, exact-matrix
comparison, and local-versus-hosted enforcement. Validation passed with 11 Bun
tests, 92 Rust tests across all targets, matrix/corpus/issue/skill and module-size
checks, and `cargo clippy --all-targets -- -D warnings`. No live provider request
was made while resolving this tooling issue.

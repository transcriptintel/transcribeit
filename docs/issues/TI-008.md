# TI-008 — Add an automation-friendly benchmark harness

## Required outcome and acceptance

Create a harness only after the corpus and expected metrics are pinned. It must
capture the existing tracked metadata schema, execute exact provider/model
matrices without exposing credentials or transcript-bearing bodies, preserve
individual failures, sanitize publishable records, and distinguish local,
hosted, warm, cold, clean, and dirty runs. Concurrency and retries must be
explicit rather than hidden by the runner.

Acceptance requires deterministic fixture selection, resumable result storage,
schema validation, and tolerance rules that acknowledge host and provider
variance. CI must not fail on a tight latency threshold or incur unbounded live
provider cost; scheduled or manually approved remote execution remains a
separate policy decision.
